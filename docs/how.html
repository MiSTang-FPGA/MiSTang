Can a Tang Nano 20K load cores from an SD card?

Short answer: yes, indirectly. A real MiSTer swaps the whole FPGA configuration from a Linux HPS. The Nano 20K has no HPS, but it has a Gowin multiboot path and a SPI flash big enough to stage a core. Everything below is marked with how sure we are.

What is verified on the real board

Measured on a Tang Nano 20K (FT2232 serial 2023030621) from node via the same jtag.mjs/gowin.mjs the browser uses.
IDCODE 0x0000081B = GW2A(R)-18(C) · Flash Winbond W25Q64 (EF 40 17, 8 MiB) · Flash read 64 KiB in 0.42 s · SRAM load of a 907 418-byte bitstream in 4.8 s at 6 MHz TCK, status 0x6020 = DONE.

The loading chain

StepMechanismStatus
1. Launcher bootsBitstream at flash 0x000000, menu CPU (RISC-V) firmware at 0x100000 — same layout as Open Pocket GBC.proven
2. Read core from SDFatFs on the soft CPU reads /MiSTang/cores/<name>.bin.proven (SD + FatFs already in Open Pocket GBC)
3. Stage in flashCPU erases 4 KiB sectors and programs 256 B pages into slot A (0x400000). ≈ 225 sectors for a 0.9 MB bitstream.proven (flash.c already does saves)
4. ReconfigureFabric pulls RECONFIG_N low; the FPGA reloads from the address in the bitstream header (key 0x52, 4 KiB granularity, UG290/UG702). Header is patchable: patchMultiboot() in Studio.proven — measured 2026-11-01: a design driving pin 9 (IOR31B) low made the FPGA reload from the header address; USERCODE changed 0x4EAC → 0xFD4B
5. Back to menuSlot A's header points to 0x000000; cores pull RECONFIG_N on a button combo.expected — same mechanism; the return trip from a flash-booted core is not yet run
RECONFIG_N test (hardware): design A (built with --multiboot_address 0x4F0000) was loaded into SRAM and pulled pin 9 low after ~5 s; design B sat in flash at 0x4F0000. About 7–8 s after load the USERCODE read over JTAG switched from A to B (B loaded directly gives the same value). No external wire was needed. Source: hwtest/reconfig/, tools/hw/reconfig_test.mjs. The test region was blank and was erased afterwards.

Why not simply …

  • Partial reconfiguration: GW2A has no ICAP-style primitive reachable from fabric.
  • Fabric drives its own JTAG / slave-SSPI: JTAG pins are dedicated and wired to the FT2232; mode pins are fixed for MSPI.
  • One giant bitstream with all cores: 20 736 LUT4 — a single NES already takes a large part of it.
No-fabric alternative that works today: Studio writes the core into the flash slot over JTAG (measured above) and tells the FPGA to reload. SD staging is the standalone version of the same thing.

Uploading a bitstream from github.io

Yes — and it is implemented. Chrome and Edge expose WebUSB on HTTPS pages, and github.io is HTTPS. The Tang Nano 20K’s on-board debugger is an FT2232 (0403:6010); channel A is JTAG. Studio speaks the FTDI MPSSE protocol directly over WebUSB, then the Gowin JTAG commands (ported from openFPGALoader): erase SRAM → XFER_WRITE → done, or JTAG-to-SPI bridge (IR 0x16) for the external flash.

OSNotes
macOS / LinuxWorks with no driver. On Linux add a udev rule for 0403:6010.
WindowsChannel A must use WinUSB — install it once with Zadig (interface 0 only; leave interface 1, the serial port, alone).
Firefox / SafariNo WebUSB. Use Chrome, Edge or the desktop build.
Sipeed FT2232 firmwareDoes not implement MPSSE 0x8E/0x8F; the driver uses TMS-only idle clocks.

Which cores can realistically come

Budget: 20 736 LUT4, 828 Kbit BSRAM, 8 MB SDRAM. Proven ports exist for NES, SNES (ROM ≤ 3.75 MB), Game Boy/Color, WonderSwan, MSX2+. 8-bit consoles and computers and small arcade boards are the next wave. Genesis, PC Engine, GBA need trimming and are research items. PSX, N64, Saturn, Mega-CD, 32X, Neo Geo, ao486 and the DVD player need far more logic or memory bandwidth and will not fit. See the catalog.
